# LayeRoom（レイルーム）

天気予報を見て服を決めても、講義室の暑さ・寒さが予想と違い、服装選びに困ることがあります。LayeRoomは、金沢の天気と大学内の室温を服選びのヒントにし、心地よく過ごせるコーディネートを考えるためのAndroidアプリです。

目指す体験は、AIによる服装の提案、似た気温の日のコーデの振り返り、先に教室を利用した人の体感の共有です。

**現在はKotlin / Jetpack ComposeによるフロントエンドのUIプロトタイプです。** 画面表示・写真選択・画面遷移・サンプルの絞り込みを実装しています。天気やセンサーの取得、AI処理、通信、保存、投稿はバックエンド接続前のため行いません。

本READMEに、現在の機能・操作・実装範囲をまとめています。

> **バックエンド接続（2026年10月25日追加）**：`local.properties` に db_server の接続先を設定すると、`:backend` モジュール経由で実際に通信・AI診断・保存・投稿を行います。設定しなければ、これまでどおりサンプルで動きます。詳しくは「バックエンド接続」を参照してください。

- 記載対象：アプリ **1.19**（versionCode：20）
- 更新日：2026年10月25日

## 画面構成

下部タブは左から次の3つです。新規起動時は中央の「ホーム」を開きます。

| タブ | 主な機能 |
| --- | --- |
| 気温別コーデ | 写真付きの過去コーデのサンプルを、気温や室温で絞り込む |
| ホーム | 金沢向けの服装の目安を見る、写真診断や場所別のAI提案へ進む |
| 今日のひろば | 場所別の口コミのサンプルを見る、体感の投稿フォームを開く |

AI機能はホームから直接利用する構成です。チャット入力欄や服管理・服登録の専用タブはありません。

## 設定・ユーザー登録

全タブ共通の右上にある歯車マークを押すと、ユーザー登録シートを開きます。

- 入力項目は**ユーザー名のみ**です。日本語入力に対応しています。
- 空欄や空白だけの場合は「登録する」を無効にし、ユーザー名を入力すると有効にします。
- 登録ボタンはシートを閉じます。実際の登録・通信・保存はバックエンド側の実装に委ねます。
- 入力値はシート内だけで保持し、閉じると破棄します。

## ホーム

### 今日の服装の目安

ホーム上部に、**金沢の天気に合わせた服装を案内するためのカード**を表示します。

- トップス：Tシャツ
- ボトムス：薄手のズボン
- 羽織り：薄手のカーディガン
- トップス・ボトムス・羽織りを等幅の3列に並べ、各列の中央に服のピクトグラムと名前を配置します。
- 下に、朝晩の冷えに備えるための短いアドバイスを表示します。

現在の内容は固定の表示サンプルです。実際の天気の取得や、天気からの服装判定は行っていません。

**このカードは教室・場所の選択とは独立しています。** ホーム右下や気温別コーデで場所を変更しても、上部の目安は変わりません。場所・気温・室温・湿度・快適さを並べた情報枠は表示せず、見出しの下から服装の目安を配置しています。

### 左下：写真でコーデ診断

1. 「写真でコーデ診断」を押すと、Android標準の写真選択画面を直接開きます。
2. 写真を1枚選ぶと、診断画面へ自動で遷移し、画像を読み込みます。
3. 読み込み成功後、写真と選択場所の情報をフロントエンド内の診断アクションに設定します。
4. 選択写真と「コーデを確認しています」という診断中の表示サンプルを表示します。

追加の確認・送信ボタンはありません。実際の画像送信・AI診断は行わず、診断結果も生成しません。

| 状況 | 動作 |
| --- | --- |
| 写真選択をキャンセル | ホームに留まり、診断アクションを作成しない |
| 画像読み込み中 | 読み込み中の表示を出す |
| 読み込み失敗・サイズ超過など | エラーと「写真を選び直す」を表示する |
| 戻る・別タブへ移動 | 画像読み込みをキャンセルし、選択写真の状態を解除する |

読み込む画像は10MB以下です。表示用に長辺が1400ピクセル以下になるよう縮小して読み込みます。アプリ独自のカメラ撮影画面は実装していません。

### 右下：○○のおすすめ

「図書館のおすすめ」など、選択した場所に合う具体的なコーデの提案画面へ進む入口です。

| 操作 | 動作 |
| --- | --- |
| ピンアイコン・「場所を選ぶ」・場所名がある枠付きボタンを押す | 下から場所選択シートを開く |
| 場所を1つ選ぶ | 場所を変更してシートを閉じる。この時点では提案アクションを作成しない |
| 場所選択ボタン以外のカード部分を押す | 固定プロンプトと場所情報を設定して、提案画面へ自動で遷移する |

固定プロンプトは **「今日の服装を提案して」** です。選択場所・その室温・金沢の気温も、操作時点の情報として一緒に保持します。

提案画面には場所・室温・金沢の気温、コーデ写真のサンプル、選択場所向けの固定アドバイス、「このコーデを保存」ボタンがあります。保存ボタンは未接続で、押しても保存処理や完了通知は行いません。AIへの実際の送信や提案生成も行いません。

## 気温別コーデ

写真付きのサンプルコーデ2件を一覧表示します。各カードには、写真・コーデ名・日付・場所・金沢の気温・室温を表示します。写真と記録は実際の利用者の履歴ではありません。

### 温度による絞り込み

| 条件 | 追加の入力・選択 | 絞り込む対象 |
| --- | --- | --- |
| すべて | なし | すべてのサンプル |
| 今の金沢 | なし | 現在の金沢のサンプル気温に近い、過去の屋外気温 |
| 今の室温 | 下に場所のプルダウンを表示 | 選択場所の室温に近い、過去の室温 |
| 温度を指定 | 下に「指定の気温（℃）」の入力欄を表示 | 入力した気温に近い、過去の屋外気温 |

- 温度差が**±2℃以内**のサンプルを表示します。
- 指定できる気温は**−50〜60℃**です。
- 不正な入力や、条件に合うコーデがない場合は案内を表示します。
- 「温度を指定」の条件表示は「指定の気温」です。「今の金沢」では「金沢の気温」と表示します。
- 「今の室温」で選んだ場所は、ホーム右下の場所別おすすめと共通です。ホーム上部の金沢向けの目安には影響しません。
- 絞り込みはアプリ内のサンプルだけを対象とし、サーバー検索は行いません。

## 今日のひろば

### 場所別の口コミを見る

1. 「今日のひろば」タブを押すと、下から場所選択シートを開きます。
2. 場所を1つ選ぶと、その場所の口コミだけを表示します。
3. すでに同じタブを開いている場合も、もう一度タップすると場所を選び直せます。
4. 画面上側の「場所を変更」ボタンからも選び直せます。

口コミには、場所・体感・コメント・相対時刻を表示します。場所別の件数を表示し、寒い体感には水色、暑い体感にはオレンジ、快適には緑のバッジを使用します。

未選択でシートを閉じた場合は場所の選択案内を表示します。選択済みの状態でキャンセルした場合は、それまでの場所を維持します。該当する口コミがない場合の案内もあります。

**ひろばの閲覧場所は、ホーム右下・気温別コーデの選択場所とは独立しています。** 口コミと時刻は固定サンプルで、取得・更新は行いません。

### 体感を投稿するフォーム

場所を選んだ後、下部タブのすぐ上に大きめの「いまの体感を投稿する」ボタンを固定表示します。ボタンを押すと投稿シートを開きます。

| 項目 | 内容 |
| --- | --- |
| 場所 | 閲覧中の場所を初期表示し、別の場所にも変更できる |
| 体感 | 快適・少し寒い・かなり寒い・少し暑いから選択 |
| ひとこと | 日本語を含むコメント入力。文字数を表示 |

空白だけではない1〜500文字のコメントで投稿ボタンを有効にします。日本語IMEの変換中の状態も保持します。

投稿するとシートを閉じます。送信・保存・完了通知は行いません。一覧への追加は行いません。フォームは常駐せず、開くためのボタンのみタブの上に固定します。口コミをスクロールしてもボタンは同じ位置に表示され、一覧には重なりません。

- 実装範囲は本READMEに記載しています。注記の非表示によって、実際の通信・AI・登録・保存・投稿の処理が追加されたわけではありません。

## バックエンド接続

バックエンドは同じプロジェクトの `backend/`（`:backend` モジュール）にあり、**端末の中で動きます**。画面は `LayeRoomViewModel` を通して呼び、`:backend` が Ubuntu 上の db_server と OpenAI を呼びます。

```
app（画面） → LayeRoomViewModel → :backend（LayeRoomBackend） → db_server（Ubuntu・PostgreSQL） / OpenAI
```

### 設定（`local.properties`。コミットしない）

```properties
DB_SERVER_URL=http://<db_serverのアドレス>:<ポート>
OPENAI_API_KEY=sk-...
# 任意: キーを端末に置かず、中継サーバー経由にするとき
# OPENAI_BASE_URL=http://<中継サーバー>/v1
```

`DB_SERVER_URL` が無いときはバックエンドを使わず、画面はサンプル（`PreviewData`）を表示します。自動テスト `FrontendUiTest` もサンプルで動きます。
`OPENAI_API_KEY` はアプリ（APK）に入るので、配布する前に中継サーバー経由にするか、使用上限を設定してください。

### 接続時の各画面

| 画面 | 接続時の動き |
| --- | --- |
| 設定・ユーザー登録 | 入力したユーザー名で db_server に利用者を作り、端末に覚える（登録中の名前を表示） |
| 場所の選択 | db_server の場所と室温・湿度（センサーのある部屋は実測、ほかは仮の値） |
| 写真でコーデ診断 | 写真を選ぶと、OpenAI で服を読み取り、選んだ場所の室温で判定・アドバイス。「このコーデを保存」で db_server に保存 |
| ○○のおすすめ | 保存した服から、選んだ場所の室温に合う上下を提案（上下を1枚にした画像つき）。服が4着未満なら気温だけの定番の提案。保存できる |
| 気温別コーデ | 保存したコーデ（写真・日付・場所・室温・金沢の気温）。絞り込みは今までと同じ |
| 今日のひろば | 選んだ場所の今日の投稿を読み込み、投稿は db_server に保存 |
| 今日の服装の目安（ホーム上部） | **サンプルのまま**（天気から目安を決める処理はまだ無い） |

ユーザー登録の前にAI診断・提案・投稿をすると、「右上の歯車からユーザー登録をしてください。」と表示します。

- `FrontendUiTest`（11件）：サンプル表示の画面
- `FrontendBackendTest`（6件）：バックエンド接続時の画面（`:backend` は本物、db_server と写真の読み取りだけ偽物）
- `:backend` のテストと本物の db_server につなぐテストは `backend/README.md` を参照

Gradle 8.11.1 は **JDK 17〜23** で動かします（JDK 25 以降では動きません）。Android Studio 付属の JDK が 25 以降の場合は、Gradle JDK に JDK 21 などを指定してください。

## フロントエンドとバックエンドの分担

| フロントエンドで実装済み | バックエンド接続後に実現する処理 |
| --- | --- |
| ユーザー登録フォーム・入力確認 | アカウント作成・認証・登録情報の保存 |
| 3タブ・場所選択・画面遷移 | 場所やセンサーデータの取得 |
| 金沢向けの服装の目安の表示枠 | 天気取得、天気に応じた目安の生成 |
| 標準写真ピッカー・写真表示・診断中とエラーの表示 | 画像送信、AIによる服装評価 |
| 固定プロンプトと場所情報の保持・提案画面 | AI提案の生成、履歴に基づく推薦 |
| サンプルコーデの温度フィルター | 過去コーデの取得、サーバー検索 |
| 保存ボタン・口コミ一覧・投稿フォーム | コーデ保存、口コミの取得・投稿、データベース |

ユーザー登録の入力UIは実装済みですが、実際のアカウント登録・認証・ログイン・GPS・不快指数の計算・服装判定・端末内へのデータ保存は実装していません。写真や操作結果は実行中のメモリー上で扱います。

### AI操作時の受け渡し

フロントエンド内では `LayeRoomViewModel.latestAiRequest` に次の情報を設定します。

| フィールド | 内容 |
| --- | --- |
| `mode` | 写真診断（`PHOTO`）またはコーデ提案（`SUGGEST`） |
| `photo` | 写真診断時に読み込んだBitmap |
| `prompt` | 提案時の固定文「今日の服装を提案して」 |
| `location` | 操作時に選択していた場所 |
| `indoorTemperature` | その場所の室温 |
| `outdoorTemperature` | 金沢の気温 |

これはアプリ内の操作状態です。サーバーAPIの仕様・エンドポイント・通信処理は定義していません。

## Android Studioで開く・更新・実行する

1. `settings.gradle.kts` がある **`codex_test` フォルダー**を開きます。親フォルダーを開く必要はありません。
2. クローン済みの場合は **Git → Pull** で `main` の更新を取得します。再クローンは不要です。
3. 黄色い帯が表示されたら **Sync Now** を押します。または **File → Sync Project with Gradle Files** を実行し、同期完了を待ちます。
4. 上部で実行構成 `app` とエミュレーターまたは実機を選び、**▶ Run** を押します。
5. エミュレーターは通常、右側のRunning Devicesに表示されます。起動・インストールが完了するとアプリが開きます。

JDKの設定エラーが出た場合は、**Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK** をAndroid Studio付属のJDK（jbr）など、JDK 17以上に設定してください。初回同期にはネット接続とAndroid SDK Platform 35が必要です。
