# LayeRoom（レイルーム）アプリ

天気予報を見て服を決めても、講義室の暑さ・寒さが予想と違い、服装選びに困ることがあります。LayeRoomは、金沢の天気と大学内の室温を服選びのヒントにし、心地よく過ごせるコーディネートを考えるためのAndroidアプリです。

Kotlin / Jetpack Composeの画面（`app/`）と、端末の中で動くバックエンド（`backend/`、`:backend` モジュール）でできています。`local.properties` に db_server の接続先を書くと、実際に通信・AI診断・保存・投稿を行います。書かなければ、アプリ内のサンプル（`PreviewData`）で動きます（「サーバーにつなぐ」を参照）。

- 記載対象：アプリ **1.19**（versionCode：20）
- 更新日：2026年10月25日

## 画面構成

下部タブは左から次の4つです。起動時は左端の「ホーム」を開きます。

| タブ | 主な機能 |
| --- | --- |
| ホーム | 金沢向けの服装の目安、写真でコーデ診断、場所別のおすすめ |
| 気温別コーデ | 保存したコーデを、気温や室温で絞り込んで振り返る |
| 今日のひろば | 場所ごとの体感の口コミを見る・投稿する |
| クローゼット | 保存した上の服・下の服の一覧と削除 |

AI機能はホームから使います。チャット入力欄はありません。

## ユーザー登録

- サーバーにつないでいて未登録のときは、**起動するとすぐ登録シートが開き、登録するまで閉じられません**（閉じるボタン・下へのスワイプ・戻るが効きません）。登録できると自動で閉じます。
- 登録後は、右上の歯車からいつでも開き直せます。このときは「閉じる」で閉じられ、登録中の名前も表示します。
- 入力項目は**ユーザー名のみ**です。日本語入力に対応しています。空欄や空白だけのときは「登録する」を押せません。
- 登録すると、db_server に利用者を作り、端末に覚えます。アプリのデータを消すと別の利用者になります。
- サンプル表示（サーバー未設定）のときは、登録を求めません。

## ホーム

### 今日の服装の目安

ホーム上部に、金沢の天気に合わせた服装の目安のカードを表示します（トップス：Tシャツ／ボトムス：薄手のズボン／羽織り：薄手のカーディガン）。3列に服のピクトグラムと名前を並べ、下に朝晩の冷えに備えるアドバイスを出します。

**今の内容は固定のサンプルです。** 天気から目安を決める処理はまだありません。場所の選択とも独立していて、場所を変えても変わりません。

### 左下：写真でコーデ診断

1. 「写真でコーデ診断」を押すと、**アプリ内のカメラ**が全画面で開きます。
   - 真ん中のボタンで撮影、右のボタンで内側・外側のカメラを切り替え、左のボタンで写真フォルダ（Android標準の写真選択）から選べます。左上の×で閉じます。
   - カメラの許可を断った場合も、写真フォルダからは選べます。2回断ったあとは、ボタンが「設定を開く」に変わります。
2. 撮影するか写真を選ぶと、診断画面に移り、写真を読み込みます（10MBまで。長辺1400ピクセル以下に縮小）。
3. サーバーにつないでいれば、OpenAIで服を読み取り、選んだ場所の室温で判定します。結果には、判定（ちょうどいい・上着を脱げばちょうどいい・暑い・寒いなど）、必要な暖かさと今の服の暖かさ（clo）、アドバイス、外での判定、切り抜いた上下の服が出ます。
4. 「このコーデを保存」で db_server に保存します。上下の服はクローゼットにも入ります。

| 状況 | 動作 |
| --- | --- |
| カメラを閉じる（左上の×・戻る） | ホームに戻る |
| 写真フォルダの選択をキャンセル | カメラに戻る |
| 画像の読み込み中 | 読み込み中の表示 |
| 読み込み失敗・サイズ超過・服が写っていないなど | 理由と「写真を選び直す」を表示（押すとカメラが開く） |
| 戻る・別タブへ移動 | 読み込みをやめ、選んだ写真を解除する |

サンプル表示のときは、写真と「コーデを確認しています」の表示までで、診断はしません。

### 右下：○○のおすすめ

選んだ場所に合うコーデの提案画面への入口です。

| 操作 | 動作 |
| --- | --- |
| ピン・「場所を選ぶ」・場所名のボタン | 場所選択シートを開く。選ぶと場所が変わる（この時点では提案しない） |
| それ以外のカード部分 | 提案画面へ移る |

サーバーにつないでいるときは次のように動きます。

- 保存した服が**4着以上**あれば、その中から選んだ場所の室温に合う上下を、毎回混ぜて選びます。昨日着た服は外します。
- まず上下の服の写真を並べた画像を出し、続けて **AIがマネキンに着せた画像**を作って差し替えます（1分ほどかかります）。作れなかったときは理由を表示し、並べた画像のままにします。
- 服が4着未満のときや、組み合わせが作れないときは、気温だけで決めた一般的な目安を出します。
- 「このコーデを保存」で、おすすめとして db_server に保存します。

サンプル表示のときは、コーデ写真のサンプルと固定のアドバイスを出します。保存ボタンを押しても保存しません。

### 表示する温度

画面上部の黒いカードに、場所・その室温・金沢の気温を出します。

- アプリを開いている間は、**1分ごと**に室温と金沢の気温を読み直します。ほかのアプリから戻ってきたときと、診断・提案を始めたときにも読み直します。
- 診断・提案の結果が届いたら、**AIが判定に使った温度**をそのまま表示します。表示とAIの温度がずれることはありません。

## 気温別コーデ

保存したコーデを新しい順に一覧表示します。各カードには、上下の服を1枚にした写真・コーデ名・日付・場所・金沢の気温・室温を出します。

| 条件 | 追加の入力・選択 | 絞り込む対象 |
| --- | --- | --- |
| すべて | なし | すべて |
| 今の金沢 | なし | 今の金沢の気温に近い、保存時の屋外気温 |
| 今の室温 | 場所のプルダウン | 選んだ場所の室温に近い、保存時の室温 |
| 温度を指定 | 「指定の気温（℃）」の入力欄 | 入力した気温に近い、保存時の屋外気温 |

- 温度差が**±2℃以内**のコーデを表示します。指定できる気温は**−50〜60℃**です。
- 不正な入力や、条件に合うコーデがないときは案内を表示します。
- 「今の室温」で選んだ場所は、ホーム右下のおすすめと共通です。

## 今日のひろば

### 口コミを見る

1. 「今日のひろば」タブを押すと、場所選択シートが開きます。同じタブをもう一度押しても選び直せます。
2. 場所を選ぶと、その場所の**今日の**口コミを新しい順に表示します。画面上側の「場所を変更」からも選び直せます。

口コミには、場所・体感・ひとこと・相対時刻（「10分前」など）を出します。寒い体感は水色、暑い体感はオレンジ、快適は緑のバッジです。ひろばの場所は、ホームやほかのタブの場所とは独立しています。

### 体感を投稿する

場所を選ぶと、下部タブのすぐ上に「いまの体感を投稿する」ボタンが出ます。押すと投稿シートが開きます。

| 項目 | 内容 |
| --- | --- |
| 場所 | 見ている場所を初期表示。ほかの場所にも変えられる |
| 体感 | 快適・少し寒い・かなり寒い・少し暑い |
| ひとこと | 1〜500文字（空白だけは不可）。文字数を表示 |

投稿すると db_server に保存し、一覧を読み直します。サンプル表示のときは、シートを閉じるだけで保存しません。

## クローゼット

写真でコーデ診断で保存した服を一覧表示します。

- 画面上側のタブで「上の服」「下の服」を切り替えます。タブには枚数も出ます（例：上の服 · 40枚）。最初は「上の服」です。
- 服は2列で、新しく保存した順に並びます。各服には、保存したときに切り抜いた写真と「白のシャツ」のような名前を出します。
- 同じ服を何回も保存していれば、その分だけ並びます（まとめません）。
- 開くたびに読み直すので、保存したばかりの服もすぐ出ます。
- 服がないときは「ホームの『写真でコーデ診断』で保存すると、ここに服が増えます」と表示します。クローゼットから服を追加することはできません。

### 削除

各服のゴミ箱を押すと「削除しますか？」と確認し、「削除する」を押したときだけ消えます。

- db_server ではデータを消さず、服に「隠す」印（`meta` の `hidden`）を付けます。画面から元に戻すことはできません。
- 消した服は、クローゼットとおすすめから外れます。**気温別コーデの過去の記録は残ります。**
- 保存した服が4着未満になったり、上か下の服がなくなったりすると、おすすめは一般的な目安に変わります。

## 共通デザイン・サンプルデータ

- 白・グレーを基調に、主な操作を黒にしたMaterial 3のデザインです。見出し・カード・シートの角丸・余白・文字サイズをそろえています。
- 温度の表示色は、22℃未満を水色、それ以上をオレンジにしています（表示上の色分けで、快適さの判定ではありません）。
- タブ・設定・カメラ・場所・保存・削除などの操作アイコンに、Googleの **Material Symbols Rounded** を使っています。アイコンはAndroid VectorDrawableとして同梱し、ネット接続・Webフォントは不要です。出典・対応表・ライセンスは [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) にあります。
- アプリアイコンの「L」を重ねたマークと、服装の目安のピクトグラム・コーデ写真のサンプルは独自の素材です。

## サーバーにつなぐ

バックエンドは `backend/`（`:backend` モジュール）にあり、**端末の中で動きます**。画面は `LayeRoomViewModel` を通して呼び、`:backend` が db_server と OpenAI を呼びます。詳しくは [backend/README.md](backend/README.md) を参照してください。

```
app（画面） → LayeRoomViewModel → :backend（LayeRoomBackend） → db_server（PostgreSQL） / OpenAI
```

### 設定（`local.properties`。コミットしない）

```properties
DB_SERVER_URL=http://<db_serverのアドレス>:<ポート>
OPENAI_API_KEY=sk-...
# 任意: キーを端末に置かず、中継サーバー経由にするとき
# OPENAI_BASE_URL=http://<中継サーバー>/v1
# 任意: マネキン画像に最初に試すモデル（使えなければ既定のモデルを順に試す）
# OPENAI_IMAGE_MODEL=gpt-image-1
```

- `DB_SERVER_URL` が無いときはバックエンドを使わず、サンプル表示になります。
- `OPENAI_API_KEY` も `OPENAI_BASE_URL` も無いときは、写真診断（「OpenAI のキーが設定されていません」と表示）とマネキン画像が使えません。おすすめは、上下の服の写真を並べた画像で出します。
- `OPENAI_API_KEY` はアプリ（APK）に入るので、配布する前に中継サーバー経由にするか、使用上限を設定してください。
- 設定を変えたら、Android Studioで Gradle の Sync をしてから実行してください。

### AI操作時の受け渡し

診断・提案を始めると、`LayeRoomViewModel.latestAiRequest` に次の情報を設定します（画面の表示用）。結果が届くと、温度はAIが使った値に置き換わります。

| フィールド | 内容 |
| --- | --- |
| `mode` | 写真診断（`PHOTO`）またはコーデ提案（`SUGGEST`） |
| `photo` | 写真診断で読み込んだBitmap |
| `prompt` | 提案時の固定文「今日の服装を提案して」 |
| `location` | 選んでいた場所 |
| `indoorTemperature` | その場所の室温 |
| `outdoorTemperature` | 金沢の気温 |

## Android Studioで開く・実行する

1. `settings.gradle.kts` がある **`Layeroom_app` フォルダー**を開きます（リポジトリのルートではありません）。
2. 黄色い帯が出たら **Sync Now** を押します。または **File → Sync Project with Gradle Files** を実行します。
3. 実行構成 `app` と、エミュレーターまたは実機を選び、**▶ Run** を押します。

Gradle 8.11.1 は **JDK 17〜23** で動かします（JDK 25 以降では動きません）。Android Studio付属のJDKが25以降の場合は、**Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK** に JDK 21 などを指定してください。初回の同期にはネット接続とAndroid SDK Platform 35が必要です。

| 構成 | バージョン |
| --- | --- |
| Gradle / Android Gradle Plugin | 8.11.1 / 8.9.2 |
| Kotlin / Compose BOM | 2.1.20 / 2025.03.01 |
| CameraX | 1.4.1 |
| 最小Android API | 26 |
| compile / target SDK | 35 |
| アプリ | 1.19（versionCode：20） |

表示名はLayeRoomです。既存アプリへ上書き更新できるよう、内部のアプリID・パッケージ名 `jp.climafit.app` は維持しています。

## テスト

`app/src/test/` の自動UIテストは、Android API 35相当のRobolectric環境で動きます。

| テスト | 件数 | 内容 |
| --- | --- | --- |
| `FrontendUiTest` | 13件 | サンプル表示の画面。タブの並び、カメラと写真選択、場所選択、気温別コーデの絞り込み、ひろばの投稿、クローゼットの切り替えと削除、登録フォーム、アプリアイコンとMaterial Symbols 19種類の描画など |
| `FrontendBackendTest` | 10件 | サーバー接続時の画面（`:backend` は本物、db_server と写真の読み取りだけ偽物）。登録、写真診断と保存、おすすめと保存、温度の読み直し、クローゼットの削除、ひろば、気温別コーデ |

`:backend` のテストは [backend/README.md](backend/README.md) を参照してください。

Windows：

```bat
gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

macOS / Linux：

```sh
bash ./gradlew assembleDebug testDebugUnitTest lintDebug
```

実機・各エミュレーター固有のカメラ、写真ピッカー、ランチャーの挙動は、自動テストの対象外です。
